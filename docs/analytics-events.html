数据埋点

医记数据指标与埋点方案

版本：MVP Draft 日期：2026-07-10 原则：隐私优先、最小必要、只采集产品决策需要的数据

1. 为什么需要埋点

医记当前最需要回答的不是“用户点击了多少按钮”，而是这些业务问题：

  1. 用户是否能完成从注册到首份资料归档？
  2. 用户是否理解“手动整理 + 就诊资料包”的产品价值？
  3. 用户是否愿意持续维护病历、用药、指标和待办？
  4. 用户是否真的在就诊前生成资料包？
  5. 家庭成员和订阅是否带来增量价值？
  6. 哪些步骤让用户流失、失败或不信任？

因此，MVP 埋点必须围绕业务闭环设计：


访问 -> 注册/登录 -> 本人建档 -> 上传资料 -> 分类归档
-> 添加药品/指标/待办 -> 搜索/时间线查看
-> 生成就诊资料包 -> 导出 PDF -> 留存/订阅

2. 合规和隐私边界

医疗健康信息属于敏感个人信息范畴。埋点不得采集病历正文、药品名称、诊断名称、检查结果原文、医院名称原文、文件名原文、邮箱明文、身份证号、手机号、原始文件 URL、分享 token、验证码、Cookie、访问令牌。

埋点只允许采集以下类型：

  • 匿名或伪匿名用户 ID。
  • 成员数量、资料数量、药品数量、指标数量等计数。
  • 文件类型、资料类型、操作结果、耗时、错误码等产品行为数据。
  • 是否完成某步骤、是否开启提醒、是否导出 PDF 等布尔或枚举数据。
  • 经白名单处理的页面、功能、按钮、套餐类型。

禁止采集字段

CategoryExamplesRule
病历正文主诉、诊断、检查结论、医嘱原文禁止
药品敏感信息药品名称、剂量、用法用量原文禁止

医院/医生医院名、科室名、医生名默认禁止；如确需分析，只采“是否填写”

3. 北极星指标

North Star Metric

每月生成过至少 1 次就诊资料包的活跃用户数。

定义：


Monthly Visit-Pack Active Users =
在自然月内完成 visit_pack_export_succeeded >= 1 的去重用户数

为什么不用“上传资料数”作为北极星：

  • 上传资料只是中间行为。
  • 医记的最终价值是就诊前可用，而不是存文件。
  • 资料包能同时验证资料整理、药品、指标、搜索、分类和 PDF 导出是否成立。

    9. Dashboards

    Dashboard 1：MVP Activation

    回答：用户有没有跑通核心闭环？

  • 注册完成数。
  • 本人建档完成率。

  • 用药提醒开启率。

  • 待办完成率。
  • 今日页访问频次。

    回答：隐私优先是否落地？

  • 授权创建/撤销次数。
  • 数据导出请求数和成功率。
  • 删除请求数和完成率。
  • 越权拦截次数。
  • 分享撤销后访问失败次数。
  • 敏感操作二次验证失败率。

    • Dashboard 4：Subscription

    回答：家庭版是否值得做？

  • 套餐页访问来源。
  • 家庭成员创建率。
  • 授权邀请/接受率。
  • 套餐选择分布。
  • 试用转订阅率。
  • 取消订阅原因。

    • 10. Implementation Recommendations

    Client vs Server

    前端埋点适合采集：

  • 页面进入。
  • 表单开始。
  • 用户点击入口。
  • 前端校验失败。

    • 后端埋点必须采集：

  • 登录成功/失败。
  • 上传成功/失败。
  • 归档成功。
  • PDF 导出成功/失败。
  • 授权、撤销、删除、导出。
  • 支付/订阅。

    • 核心业务指标以后端事件为准，前端事件只能辅助分析流失。

    Event Pipeline

    MVP 可以先用数据库表或轻量事件表：

    
product_events
- id
- event_name
- user_id_hash
- anonymous_id
- session_id
- properties_json
- occurred_at
- received_at
- environment

    要求：

  • 所有 properties 进入白名单校验。
  • 丢弃禁止字段。
  • 对邮箱等身份标识只保存哈希或不保存。
  • 服务端补充 received_at。
  • 失败事件也要记录，但只记录错误码，不记录请求正文。

    • Error Codes

    错误码必须标准化，便于分析：

    
AUTH_CODE_EXPIRED

    11. QA Checklist for Analytics

  • [ ] 每个 P0 用户故事至少有 1 个成功事件和 1 个失败事件。
  • [ ] Activation Funnel 能从事件直接计算。
  • [ ] PDF 导出成功率能从后端事件直接计算。
  • [ ] 不采集病历正文、药品名称、诊断名称、指标具体值。
  • [ ] 搜索事件不采集原始搜索词。
  • [ ] 分享 token、文件 URL、验证码、Cookie、Token 不进入埋点。
  • [ ] 所有事件属性经过白名单校验。
  • [ ] Staging 和 Production 数据隔离。
  • [ ] 用户删除/注销后，分析数据只保留不可识别的聚合数据或按政策处理。

    13. Source Notes

    • 《中华人民共和国个人信息保护法》要求个人信息处理遵循合法、正当、必要、诚信原则，并限于实现处理目的的最小范围。
    • 中国网信网对敏感个人信息的解读明确提到医疗健康信息属于敏感个人信息。
    • 《网络数据安全管理条例》自 2025-01-01 起施行，正式公开服务前需要纳入数据安全和个人信息处理合规评估。
