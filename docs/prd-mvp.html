医记 PRD：上线网页 MVP

版本：MVP / V1.0 产品定义稿 日期：2026-07-10 状态：Draft 产品形态：已上线的移动端优先响应式网页 核心原则：隐私优先

1. Executive Summary

医记是一款帮助患者本人管理病历和药物的网页产品。它解决的核心问题是：用户的病历、检查报告、处方、用药记录和就诊资料散落在相册、纸质文件、医院网站和不同平台里，真正看病时很难快速整理成一份医生能看懂的资料。

本版本的目标不是做 AI 医生，也不做 OCR 自动识别，而是先把“手动上传、分类整理、日常维护、就诊前生成完整资料包”的闭环跑通。成功标准是：用户在一次就诊前，可以生成一份完整、可导出的就诊资料包。

2. Background & Context

旧版文档中，医记曾包含 OCR、AI 归类、摘要生成、药品扫描等能力。但当前产品决策明确：MVP 暂不引入 AI/OCR，因为识别能力不稳定且医疗场景风险高。

因此，新版 PRD 将产品重心调整为：

  • 用户自己上传原始资料。
  • 用户自己填写或核对结构化字段。
  • 系统负责安全保存、分类、搜索、时间线、提醒和导出。
  • 所有医疗事实必须可追溯到用户录入或原始资料。
  • 产品不提供诊断、治疗建议、药品替代建议或剂量调整建议。

旧版 V1.3 的主线仍然保留：


建档 -> 补全 -> 维护 -> 就诊使用

但其中“AI 识别”改为“用户手动录入 / 用户核对归档”。

3. Objectives & Success Metrics

Goals

  1. 让患者本人能够把散落在不同医院网站、相册、纸质材料中的病历资料集中保存和分类。
  2. 让用户能够维护当前用药、健康指标、复查和资料处理待办。
  3. 让用户在就诊前选择相关资料，生成一份完整的 PDF 就诊资料包。
  4. 建立隐私优先的数据权限、授权、删除和导出机制。
  5. 验证订阅会员家庭版是否有付费价值。

Non-Goals

  • 不做 AI 诊断、疾病概率预测、治疗方案推荐。
  • 不做 OCR 自动识别作为 MVP 必需能力。
  • 不自动推荐用药、改变剂量或判断药品替代关系。
  • 不接入医院 HIS、电子病历平台或医保系统。
  • 不做医生工作台、问诊社区、药品交易或导流问诊。
  • 不默认允许家庭成员读取成年人的病历，必须经过明确授权。

    Data Instrumentation

    MVP 必须同步建设最小埋点能力，否则无法判断产品是否跑通。第一批埋点以核心闭环为准：注册、建档、上传、归档、药品、指标、待办、资料包创建、PDF 导出、数据导出、删除请求。

    埋点不得采集病历正文、药品名称、诊断名称、医院名称原文、指标具体数值、原始搜索词、文件 URL、分享 token、验证码、Cookie 或访问令牌。详细方案见 医记_数据指标与埋点方案_2026-07-10.md。

    4. Target Users & Segments

    Primary User

    患者本人。

    Initial Segment

    20-45 岁、有跨医院就诊、体检、慢病复诊或长期用药经历的用户。他们能独立使用网页、邮箱验证和文件上传，也更可能为家庭版订阅付费。

    Secondary Users

    • 替父母整理病历和药物的子女。
    • 替孩子管理病历、用药和复查的父母。
    • 慢病患者或长期复查人群。

    MVP 以患者本人为第一优先用户，家庭成员能力保留，但不得压过本人闭环。

    5. Core User Journey

    
邮箱验证登录
-> 创建本人健康档案
-> 上传病历、检查报告、处方或其他资料
-> 选择资料类型、医院、日期、关联问题和所属成员
-> 添加当前用药和服药提醒
-> 记录关键指标
-> 创建复查、用药、资料补全等待办
-> 通过搜索或时间线持续维护
-> 就诊前选择相关资料
-> 补充本次就诊目的和近期情况
-> 生成并核对就诊资料包
-> 导出 PDF

    6. Requirements

    P0 - Must Have

    #RequirementAcceptance Criteria P0-1邮箱验证登录用户可通过邮箱验证码注册/登录；验证码不在生产环境明文展示；可退出登录 P0-2本人健康档案用户首次进入后创建本人档案；至少支持姓名/昵称、性别、出生年月、过敏史、长期疾病 P0-3家庭成员管理支持创建家庭成员并切换；每份资料必须归属于一个成员；默认以本人为主 P0-4病历上传支持图片、PDF、常见文档上传；保存原始文件；记录文件名、类型、上传时间、所属成员 P0-5病历分类用户可手动选择资料类型、就诊日期、医院/机构、科室、健康问题标签 P0-6搜索支持按成员、资料类型、医院、日期、关键词搜索 P0-7时间线按成员展示就诊和资料时间线；支持按类型筛选 P0-8用药管理与提醒支持药品名称、规格、用途备注、用法用量原文、开始/结束日期、提醒时间 P0-9指标记录支持体重、血压、血糖、心率、体温；每条指标必须有日期和来源 P0-10待办事项支持复查、用药、资料补全、资料核对等类型；可完成/延期 P0-11就诊资料包 PDF用户选择成员、就诊目的、相关资料和近期情况后生成 PDF P0-12隐私授权敏感健康信息处理、家庭成员访问、导出和分享需要明确授权记录 P0-13数据导出与删除用户可导出结构化数据和原始文件；可删除单份资料；可申请账号注销 P0-14安全审计登录、上传、查看、修改、删除、导出、授权等关键操作写入审计 P0-15数据埋点支持核心闭环漏斗、PDF 导出成功率、错误码和隐私相关操作分析；不得采集医疗正文和直接身份信息

    9. Timeline & Phasing

    Phase 0 - 已上线网页梳理

  • 明确当前线上版本与 PRD 的差距。
  • 移除或隐藏 AI/OCR 承诺文案。
  • 将首页主线调整为“今日”和“我要去看医生”。

    • Phase 1 - MVP 闭环

  • 邮箱登录、本人与家庭成员、病历上传/分类、用药、指标、待办、搜索、时间线、PDF 资料包、隐私授权。
  • 完成真实用户端到端测试：注册、建档、上传、分类、添加药品、记录指标、生成 PDF、删除。

    • Phase 2 - 家庭订阅验证

  • 家庭成员授权、订阅套餐、容量/成员限制、导出与撤销能力。
  • 观察是否愿意为家庭版付费。

    • Phase 3 - 合规与国内化

  • ICP/公安备案评估。
  • 中国大陆可访问、可搜索、可收信的生产方案。
  • 敏感个人信息处理影响评估和第三方服务清单。
